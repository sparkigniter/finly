---

## Reporting a Vulnerability

We take security seriously and appreciate responsible disclosure of any security concerns, even during development.

### How to Report

If you discover a security vulnerability or security concern:

1. **Email us directly:** vikasmbiradargoudar@gmail.com
2. **DO NOT open a public GitHub issue**
3. **Include the following details:**
   - Description of the vulnerability or security concern
   - Steps to reproduce (if applicable)
   - Potential impact
   - Suggested fix (if you have one)

### What to Expect

- **Initial Response:** Within 48 hours
- **Acknowledgment:** We will confirm receipt and begin investigating
- **Fix Timeline:** We aim to address security issues promptly, typically within 1-2 weeks
- **Follow-up:** We will notify you when the issue is resolved

### Scope

We are interested in security reports regarding:

- ✅ Vulnerabilities in the application code
- ✅ Configuration security issues
- ✅ Data handling and privacy concerns
- ✅ Authentication/Authorization flaws
- ✅ Dependency vulnerabilities
- ✅ Infrastructure or deployment security issues

## Security Best Practices for Contributors

If you're contributing to this project:

- ✅ Never commit sensitive data (API keys, passwords, credentials)
- ✅ Use environment variables for configuration
- ✅ Follow OWASP Top 10 guidelines
- ✅ Validate and sanitize all user inputs
- ✅ Keep dependencies updated
- ✅ Review security considerations in code reviews

## Before Using in Production

Before deploying this project in a production environment, please:

1. ✅ Conduct a comprehensive security audit
2. ✅ Review all dependencies for known vulnerabilities
3. ✅ Implement proper authentication and authorization
4. ✅ Set up logging and monitoring
5. ✅ Configure secure deployment practices
6. ✅ Test thoroughly in a staging environment
